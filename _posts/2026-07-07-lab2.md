## 实验目的与主要内容

**实验目的：**
*   理解并掌握 MIPS 4Kc 体系结构下的内存映射布局。
*   实现物理内存的管理，建立以页为单位的分配与回收机制。
*   建立两级页表结构，实现虚拟地址空间到物理空间的动态映射。
*   理解硬件 MMU 与软件 TLB 重填的关系，实现 TLB 的维护与缺失后的被动页面分配。

**主要内容：**
*   **物理端：** 初始化 `pages` 数组，利用链表宏维护 `page_free_list`，实现 `page_alloc` 和 `page_free`。
*   **虚拟端：** 编写页表检索函数 `pgdir_walk` 和地址映射函数 `page_insert`。
*   **硬件端：** 在汇编层处理 TLB 异常，在 C 语言层实现 `_do_tlb_refill`，完成缺失页面的重填。

---

## 实验的主要组成部分

本实验逻辑上分为三个部分：

1.  **物理内存管理：**
    *   基于 `freemem` 的早期内存分配（`alloc` 函数）。
    *   空闲页面的管理：使用双向链表宏，通过引用计数 `pp_ref` 判断页面生命周期。

2.  **两级页表管理：**
    *   利用 MIPS 的 10位-10位-12位 的结构拆分虚拟地址。
    *   通过 `pgdir_walk` 实现页表的动态生长（即二级页表的按需创建）。
    *   实现地址空间的映射与解除映射。

3.  **TLB 维护与重填：**
    *   通过 `tlb_out` 和 `tlb_invalidate` 保证 TLB 缓存与内存页表的一致性。
    *   实现 `do_tlb_refill` 异常处理程序，将内存中的映射项通过 CP0 寄存器搬运至 TLB。

##  实验中的难点总结

1.  **二级指针的理解与使用：** 尤其是在 `pgdir_walk(..., Pte **ppte)` 中，需要理解为什么传入的是指针的地址。如果不能区分“指针的值”和“存放指针的地址”，会导致内存读写异常。
2.  **自映射机制（Self-Mapping）：** 理解如何通过页目录指向自身，从而在虚拟空间中开辟出一片可以直接操作整个页表结构的 4MB 区域。
3.  **TLB 的奇偶页对齐：** MIPS 的 TLB 一次重填两页。在 `_do_tlb_refill` 中，必须对 `ppte` 进行 8 字节对齐，并正确右移 6 位以适配硬件 `EntryLo` 寄存器的格式要求。
4.  **虚实地址转换的频率：** 混淆物理地址与虚拟地址（kseg0）。在代码中必须时刻清醒：页表项里存的是物理地址，而内核代码读写必须使用 `KADDR` 转换后的虚拟地址。

## Thinking 部分解答

### Thinking 2.1：虚拟地址与物理地址

*   **指针变量：** 被视为**虚拟地址**。C 程序运行在虚存空间，指针的值由编译器和链接器分配。
*   **lw/sw 指令：** 使用的也是**虚拟地址**。这些地址会经过硬件 MMU/TLB 翻译后，才会发出真正的物理寻址请求。

### Thinking 2.2：宏实现链表的好处
*   **泛型支持：** C 语言不支持模板，使用宏可以实现“侵入式链表”，让同一套逻辑支持多种数据结构（如 `Page`、`Env`）。
*   **零性能损耗：** 宏在预编译阶段展开，没有函数调用的开销，对于内核底层的高效操作至关重要。

### Thinking 2.3：Page_list 结构梳理
*   `Page_list` 展开后是一个包含 `struct Page *lh_first` 的结构体。
*   每个 `struct Page` 内部包含 `pp_link`，其成员 `le_next` 指向下一个 Page，`le_prev` 指向前一个 Page 的 `le_next` 指针的地址。

### Thinking 2.4：ASID 必要性与数量

*   **必要性：** ASID 用于区分不同进程的虚拟地址空间。有了 ASID，不同进程相同的虚拟地址可以同时存在于 TLB 中而不会冲突，避免了进程切换时频繁刷新（Flush）整个 TLB 带来的性能抖动。
*   **最大数量：** 在 MIPS 4Kc 中，ASID 通常占据 8 位，因此最多可容纳 $$2^8 = 256$$ 个不同的地址空间标识。

### Thinking 2.5：tlb_invalidate 与 tlb_out
*   **关系：** `tlb_invalidate` 是 C 语言层面的接口，它调用汇编函数 `tlb_out`。
*   **作用：** `tlb_invalidate` 的作用是：当页表映射发生改变时，强制清除 TLB 中可能存在的旧缓存项。
*   **tlb_out 解释：**
    1. 将要找的 VA 放入 `EntryHi`。
    2. 执行 `tlbp` 探测。
    3. 如果查到了（`Index >= 0`），将 `EntryHi/Lo` 清零。
    4. 执行 `tlbwi` 将该索引处的 TLB 项物理抹除。

### Thinking 2.6：函数调用与 CPU 访存流程
*   当用户程序访问一个虚拟地址时，硬件先查 TLB。
*   若 TLB Miss，触发异常，跳转到 `do_tlb_refill`（汇编）。
*   汇编调用 `_do_tlb_refill`（C）。
*   C 函数内部调用 `page_lookup` 查页表。
*   若页表也没有，调用 `passive_alloc` 分配内存。
*   最后层层返回，由汇编将新项填入 TLB。

### Thinking 2.7：其他体系结构对比（RISC-V）

*   **RISC-V 内存管理：** 采用页表树结构（如 Sv32/Sv39）。与 MIPS 最大的区别是：RISC-V 的硬件通常会自动遍历页表（Hardware Page Table Walker）。当 TLB Miss 时，硬件会自动查内存页表并填充 TLB，只有在页表项无效时才会触发 Page Fault。这减少了软件处理 TLB Miss 的负担。

uint32_t read_phys_word(u_long pa) {
	// return (volatile uint32_t*)KADDR(pa);
	// or:
	struct Page* page = pa2page(pa & 0xfffff000);
	u_long offset = pa & (PAGE_SIZE - 1);
	u_long kva = page2kva(page);
	return *((uint32_t*)(kva + offset));
}

void write_phys_word(u_long pa, uint32_t value) {
	struct Page* page = pa2page(pa & 0xfffff000);
	u_long offset = pa & (PAGE_SIZE - 1);
	u_long kva = page2kva(page);
	*((uint32_t*)(kva + offset)) = value;
}

int count_mapped_pages(Pde* pgdir, u_long va_start, u_long va_end) {

	for (; va < va_end; va += PAGE_SIZE) {
		if (pgdir[PDX(va)] & PTE_V) {
			Pte *pte;

				return -1;

	}
	return mapped;
}
